# Nodus Rules

## 处理范围

同步 blackmatrix7/ios_rule_script 的全部 Clash LIST、YAML、TXT 规则文件，包含嵌套目录；目录和文件划分以上游为准，每个源文件独立转换、合并。上游 YAML 保留原文件名，LIST、TXT 在完整文件名后追加 `.yaml`，例如 `Apple.list.yaml`、`Apple.yaml`、`Apple_Domain.txt.yaml`，避免同名文件互相覆盖。

公开网络搜索按集合查找候选，只自动补充目标服务自有域名及明确允许的第三方遥测主机。Google Fonts、Google Storage、公共 CDN、支付及客服等通用第三方资源不会因为被目标服务调用就加入其集合。

候选搜索面向全部集合，只有具备归属依据的候选才能自动入库。当前已登记部分集合的可信域名依据，其余集合记录候选并标记待补充归属依据，不根据品牌名称或搜索排名猜测所有权。这一限制用于搜索新增；上游已有条件仍按原集合转换，不把上游分类当作域名所有权审计。

## 规则同步合并逻辑

远程规则集内合并逻辑：protocol → port → domain → domain-suffix → domain-keyword → ip-cidr。远程规则集只声明条件，不携带策略。

1. 每天 **00:00、12:00 UTC** 检查，也可手动运行。读取上游规则文件的 **Last commit date**；日期未变、没有新的有效补充、输出格式未迁移时，跳过对应 YAML，不改动其核对时间。README 独立核对上游当前正文，变化时更新。首次生成、缺失文件和生成模板迁移单独处理，不使用内容指纹。
2. 已核实并登记的补充规则每次同步直接参与对应集合的合并，不依赖搜索轮询或摘要命中。搜索按集合轮询，每轮最多 24 个集合、最长约 90 秒；进度写入同步记录，后续继续覆盖其他集合。公开搜索失败或结果无法核实归属时不新增规则，不影响可信上游同步。搜索结果不是自动入库许可。
3. 新规则只并入对应集合。手工与对应输出同名的规则直接合并，不保存手工原文副本，也不生成公共搜索规则集。已合并条件不因上游后来删除而自动移除。旧版 LIST 输出的已合并条件迁到对应 `.list.yaml`，不混入同目录其他 YAML/TXT 版本；搜索补充继续只作用于对应 LIST 集合。
4. 按 Nodus Core 的保守规则归一化、去重和裁剪，保留同类原始顺序；只去除可证明被先前同类条件完整覆盖的规则，跨类型和部分重叠继续保留。远程正文没有策略，不擅自裁决直连／代理冲突；依赖最终策略的 IP、端口裁剪交给 Core。
5. 每份规则集保持单文件，不拆分、不截断。头注释保留名称、来源核对时间（**UTC，精确到分钟**）、总数和各类型数量。各集合 README 沿用上游正文和排版，仅替换本次已同步规则的原始、CDN 及代理下载 URL；来源、致谢和其他链接保持原样，不附带 `README.upstream.md` 副本。上游使用说明与统计仍描述上游格式，Nodus 转换限制见同步说明。
6. 不能转换的条件、搜索候选及失败原因写入同步记录。只有实际文件变更才提交。
